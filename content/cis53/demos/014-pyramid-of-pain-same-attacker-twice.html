Same attacker, twice: what the Pyramid of Pain looks like in a rule

Two captures, a week apart. In wave 1 host 10.0.0.31 downloads a file and then polls a server about once a minute. An analyst writes three indicator rules from it. In wave 2 the same crew hits 10.0.0.38 with a new IP, a new domain, a new file and a new user agent. Which rules still work?

Download and open

  • class5-wave1.pcap — 12 minutes, host 10.0.0.31, with office noise
  • class5-wave2.pcap — 12 minutes, host 10.0.0.38, a new IP, domain, file hash and user agent
  • class5-iocs.txt — the indicator list the analyst wrote after wave 1
  • class5-sha256.list — the hash list Suricata reads
  • class5-suricata.rules — three indicator rules, one behavior rule, one anti-example

01Run the rules on wave 1.

suricata -r class5-wave1.pcap -S class5-suricata.rules -l out1 -k none
grep -o 'CIS53 [^[]*' out1/fast.log | sort | uniq -c
Answer

All of them fire: the IP rule (12 times, once per connection), the domain rule (once, at the DNS lookup), the hash rule (once, on the download), the behavior rule (twice, because the threshold fires every five polls) and the user agent rule (12 times). Wave 1 is the capture the rules were written from, so of course they match.

02Run the same rules on wave 2.

suricata -r class5-wave2.pcap -S class5-suricata.rules -l out2 -k none
grep -o 'CIS53 [^[]*' out2/fast.log | sort | uniq -c
Answer

Only CIS53 behavior: periodic poll to outside host fires, twice. The IP, domain and hash rules are silent because the attacker changed all three. The user agent rule is silent too: wave 2 used python-requests/2.32.3, one version higher. This is the Pyramid of Pain in one screen. Hashes, IPs and domains cost the attacker almost nothing to change; the way the implant polls costs them a rewrite.

03Read what the behavior rule actually keys on.

grep 9200010 class5-suricata.rules | cut -c1-400
Answer

It keys on the shape of the request, not the destination: a GET whose URI starts with /api/v1/poll?id= followed by eight hex characters, from a host inside to a host outside, five times in ten minutes. Roddie Ch. 7 calls this moving from indicators to adversary behavior. It is still a guess about the attacker's code, which they can change, so it sits higher on the pyramid but not at the top.

04Count what the rule would cost you.

suricata -r class5-hunt.pcap -S class5-suricata.rules -l out3 -k none
wc -l out3/fast.log
Answer

Run the same rules over thirty minutes of ordinary traffic (the Demo 15 capture, which has a build server polling an internal API every 30 seconds). Zero alerts, so the behavior rule did not cost any false positives here. The reason is in the header: $HOME_NET -> $EXTERNAL_NET, so the internal health check never matches. A behavioral rule needs a sentence like that in its description saying what it was tested against.

05Write the confidence line for the indicator list.

cat class5-iocs.txt
Answer

Brown and Roberts (Ch. 2) separate data from intelligence by context. This file is data: three values with no source, no date and no confidence. A useful version says where each value came from, when it was collected, how sure you are, and when it should expire. For example: ip 198.51.100.77, seen contacting 10.0.0.31 on Nov 13, source: our own sensor, confidence: high for the date seen, expires in 14 days.
