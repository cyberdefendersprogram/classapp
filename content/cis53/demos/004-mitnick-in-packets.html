Class 2 demo · Case Study 1

Mitnick in packets

This capture is built to match the published description of the attack (Shimomura's account and the Bellovin sequence-number paper). It is a reconstruction with private addresses, not the original evidence. Use it to practice the sensor view you described in Case Study 1.

Download and open

  • mitnick-reconstruction.pcap — 117 packets: finger and RPC probes, SYN flood, 20 ISN probes, spoofed handshake, rsh command

Open the file in Wireshark (File → Open) or run the tcpdump / tshark lines below. All traffic is synthetic and uses private or documentation addresses.

01Who is talking? Open Statistics → Conversations (IPv4 and TCP).

Statistics > Conversations > TCP
Answer

10.0.0.66 is the attacker, 10.0.0.20 is the trusted server, 10.0.0.30 is the target (the X terminal), and 10.0.0.99 is a forged source address that never answers.

02Find the recon.

tcp.port == 79 || udp.port == 111
Answer

Finger (79) to the target and the server, and a UDP probe to port 111 (RPC portmapper). This is the early warning. No tool in 1994 raised an alert on it.

03Find the SYN flood.

tcp.flags.syn == 1 && tcp.flags.ack == 0 && tcp.dstport == 514
Statistics > Conversations, sort by packets
Answer

30 SYNs from 10.0.0.99 to port 514 (rsh) on 10.0.0.20 with no replies. The flood fills the server's connection queue so it cannot answer the target later. Ask: what ratio of SYN to SYN-ACK would you alert on?

04Read the sequence numbers the target hands out.

tcp.flags.syn == 1 && tcp.flags.ack == 1 && ip.src == 10.0.0.30
Edit > Preferences > Protocols > TCP > uncheck "Relative sequence numbers"
Answer

Twenty SYN-ACKs from the target, each initial sequence number 128,000 higher than the last. That fixed step is what makes the next one predictable. Each probe ends with an immediate RST from the attacker.

05Find the spoofed handshake.

ip.src == 10.0.0.20 && ip.dst == 10.0.0.30 && tcp.dstport == 514
Answer

Frames 112, 114 and 115: a SYN, then an ACK with exactly the predicted number, then data. Frame 113 is the target answering the server, who is silent because of the flood, so nobody resets the forged session.

06Read the payload.

Right-click frame 115 > Follow > TCP Stream
or: tcp.dstport == 514 && tcp.len > 0
Answer

The rsh command echoes "+ +" into /.rhosts, which makes the target trust everyone. Cleartext, so any sensor that stored full content could read it.
