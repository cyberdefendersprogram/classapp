Hunt: one quiet beacon in thirty minutes of Zeek logs

No alert fired on this capture (try it). Your hypothesis: a host is calling out to a rare destination on a schedule. The data is Zeek conn.log. The query is one awk script. The hard part is validation.

Download and open

  • class5-hunt.pcap — 30 minutes, nine hosts, office noise plus one beacon and three decoys

01Confirm that the sensor was quiet.

mkdir o && suricata -r class5-hunt.pcap -S class5-suricata.rules -l o -k none && wc -l o/fast.log
zeek -r class5-hunt.pcap
Answer

Zero alerts from class5-suricata.rules. (Run the Class 4 rules instead and you get 60 alerts, every one from the weak python-requests user agent rule on the build server 10.0.0.60, and none from the kiosk.) The beacon is a GET for a one-pixel image, so no upload rule and no URI rule matches. Hunting starts where alerts stop. Zeek writes conn.log, dns.log, http.log, ssl.log, files.log and ntp.log.

02Hypothesis and query: which pairs talk on a schedule?

zeek-cut ts id.orig_h id.resp_h id.resp_p proto < conn.log | sort -k2,2 -k3,3 -k4,4 -k1,1n | awk '
{ k=$2" "$3" "$4"/"$5 }
k==pk { d=$1-pt; n[k]++; s[k]+=d; ss[k]+=d*d }
{ pk=k; pt=$1 }
END { for (k in n) if (n[k]>=8) { m=s[k]/n[k]; sd=sqrt(ss[k]/n[k]-m*m);
  printf "%-42s n=%3d mean=%6.1fs cv=%.2f\n", k, n[k]+1, m, sd/m } }' | sort -t= -k4 -n
Answer

For each source, destination and port the script finds the gap between connections, then reports the mean gap and the coefficient of variation (cv, the standard deviation divided by the mean). A low cv means very regular. The top of the list:

10.0.0.15 10.0.0.2 123/udp       n= 29 mean= 64.0s cv=0.00
10.0.0.60 10.0.0.51 80/tcp       n= 60 mean= 30.0s cv=0.00
10.0.0.52 203.0.113.99 80/tcp    n= 21 mean= 87.4s cv=0.04

Three suspects. Human browsing sits at cv 0.3 to 0.9. Note the real beacon has some jitter (cv 0.04), so a filter that demands cv 0.00 would have found only the decoys.

03Validate with context: who are these hosts?

zeek-cut id.orig_h id.resp_h id.resp_p < conn.log | sort | uniq -c | sort -rn | grep -E '10.0.0.(15|60|52)'
# inventory: .15 front-office PC, .60 build server, .52 reception kiosk
Answer

Suspect 1 is a PC talking to the internal time server on UDP 123: clock sync. Suspect 2 is the build server polling an internal API: a health check. Both destinations are inside the network. Suspect 3 is a reception kiosk calling an outside address every 87 seconds. A kiosk that only runs a browser has no reason to do that. Context took three leads down to one.

04Look at what the beacon sends and gets back.

zeek-cut host uri user_agent < http.log | grep assets-front | head -3
zeek-cut id.resp_h orig_bytes resp_bytes < conn.log | grep 203.0.113.99 | sort | uniq -c
Answer

Every request is GET /static/px.gif?c=<6 hex> to cdn.assets-front.test, always 164 bytes out and 107 back, with a normal desktop Chrome user agent. The random query value defeats caching and carries a tag. The first DNS lookup of the name came at 09:00:29, right before the first request. Constant sizes and a constant interval are the beacon's fingerprint.

05Check the AI agent, the third decoy.

zeek-cut ts id.orig_h id.resp_h id.resp_p resp_bytes < conn.log | awk '$2=="10.0.0.77" && $4==443'
Answer

The support agent host 10.0.0.77 makes six TLS sessions to api.llm-vendor.test, each receiving 60 to 220 KB at irregular times. It only appears in the regularity query if you lower the count threshold to 5, and then with a high cv. Streaming model answers look different from a beacon: big, bursty, irregular. It is on the approved list, so it closes. This is the Class 2 false-positive lesson again.

06Turn the hunt into a detection.

# Suricata: threshold on a specific destination is an IoC. What generalizes?
# Candidate: internal host with a browser UA, 5+ GETs to one outside host, constant 164/107 byte exchanges
# Where would you run it? (Zeek script, SIEM scheduled search)
Answer

The last step of the hunting loop is to record and automate. A scheduled SIEM search over conn.log for one inside host making 8 or more connections to one outside host with cv under 0.15 would have found this on day one. Expect decoys and keep a short allowlist, with an owner and a review date for each entry.
