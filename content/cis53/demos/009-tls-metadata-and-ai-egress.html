Class 3 demo · TLS and the AI thread

TLS without decrypting, and AI egress

Everything in this capture is encrypted, yet one host is clearly in trouble. Find which AI services were contacted, who is not supposed to be there, and how much data left. Then say what you still do not know.

Download and open

  • tls-metadata-ai-egress.pcap — 675 packets: seven TLS sessions to AI and ordinary sites, with DNS lookups

All traffic is synthetic. Hosts use private or documentation addresses and domains end in .test or .example. Nothing in the file is real malware. The AI provider names appear only as SNI labels in synthetic sessions; no real provider traffic is in the file.

01Which names did each host connect to?

tls.handshake.type == 1
Add columns: ip.src, tls.handshake.extensions_server_name
Answer

Seven sessions. The SNI shows www.merritt.example, docs.corp.test, api.anthropic.com, api.openai.com (three times, from 10.0.0.60) and chat.fastpaste-ai.test from 10.0.0.44. The DNS lookups just before each connection say the same thing, which is why DNS is the cheapest AI-usage signal you have.

02Who uploaded the most?

Statistics > Conversations > TCP, sort by bytes A to B
Answer

10.0.0.44 sent about 665 kB to 192.0.2.99 (port 443) and received about 4 kB. Every other session sent between 1 and 5 kB and received more than it sent. A chat or API call sends a little and receives a lot; this is the opposite. Direction matters more than total size.

03What does the certificate say?

tls.handshake.type == 11
Answer

Only one frame matches. That session negotiated TLS 1.2, so the certificate crossed in clear: subject chat.fastpaste-ai.test, issuer FastPaste Free CA (organization Unknown Hosting Ltd), valid 90 days from 1 October 2026, so about five weeks old. A new, free, short-lived certificate on an unfamiliar name is a reputation clue.

The other six sessions use TLS 1.3, which encrypts the certificate. Same filter, no hits. That is the first thing encryption took away.

04Fingerprint the clients.

tls.handshake.type == 1
Add columns: tls.handshake.ja3, tls.handshake.ja4
Answer

JA3 and JA4 summarize how a client builds its ClientHello: TLS version, ciphers, extensions. 10.0.0.15 (a browser-like client) has the same fingerprint (7e5d861e…) for three different destinations. 10.0.0.60 (a script) has another (9ffabb2d…) for all three OpenAI calls. 10.0.0.44 has a third, TLS 1.2 only, which does not match the other two. The fingerprint tells you what is talking, not where it is talking to, so it survives a change of destination. (Needs Wireshark 4.2 or later for JA4. Chrome now randomizes extension order, so JA3 alone is unstable for it; JA4 sorts the extensions to compensate.)

05Is the pattern a person or a program?

tls.handshake.type == 1 && ip.src == 10.0.0.60
Statistics > I/O Graphs
Answer

10.0.0.60 contacts api.openai.com at 8, 38 and 68 seconds with about 3 kB up and 12 to 14 kB down each time. That regularity is an application calling an API on a schedule. If it is on your approved list (a server owned by a team that uses the service) it is fine. If it is not on the list, it is shadow AI. Without an allowlist you cannot tell, which is the point of the AI thread.

06Write the detection.

Zeek: ssl.log server_name in (unapproved AI list) OR conn.log orig_bytes > 500000 to a name not on the allowlist
Suricata: alert tls $HOME_NET any -> $EXTERNAL_NET 443 (msg:"AI service not on allowlist"; tls.sni; content:"fastpaste-ai"; sid:1000301; rev:1;)
Sigma (proxy): c-uri-domain|contains: fastpaste-ai  and  cs-bytes|gte: 500000
Answer

These are sketches to adapt, not tested rules. Ask what the false positives are: a developer uploading a large file to an approved service, a backup job, a video call. Add the host identity: who is 10.0.0.44 (a laptop, a build server)? A DHCP lease or an asset record answers that, not the packets.

07What can you not know?

Answer

You cannot see what was in the upload (source code, a customer list, a meeting transcript), whether the service kept it or trained on it, which user was logged in, or whether the upload was approved by someone. Only a proxy with TLS inspection, a DLP tool or the endpoint can answer those. Say this in the same sentence as your finding. Example: "10.0.0.44 sent about 665 kB to an unapproved AI service at 09:00:50; the content is unknown and needs a proxy log or endpoint check."
