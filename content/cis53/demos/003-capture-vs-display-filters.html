Class 2 demo · Bejtlich Ch. 6–7

Capture vs display filters

Same file, two filter languages. Try each question in Wireshark with a display filter, then again on the command line with tcpdump or tshark (the book's Chapter 6 tools).

Download and open

  • class2-filters.pcap — 72 packets: ARP, DNS, HTTP (curl and a browser), TLS to an AI API, SSH, ICMP, one reset

Open the file in Wireshark (File → Open) or run the tcpdump / tshark lines below. All traffic is synthetic and uses private or documentation addresses.

01How many DNS queries are there, and for which names?

Display: dns.flags.response == 0
Capture/BPF: tcpdump -n -r class2-filters.pcap "udp port 53"
tshark: tshark -r class2-filters.pcap -Y "dns.flags.response==0" -T fields -e dns.qry.name
Answer

Three: www.example.test, api.llm-provider.test and updates.example.test. In Wireshark add dns.qry.name as a column (right-click the field, Apply as Column).

02Show only what host 10.0.0.5 sent or received.

Display: ip.addr == 10.0.0.5
BPF:     host 10.0.0.5
One direction only: ip.src == 10.0.0.5   /   src host 10.0.0.5
Answer

Everything in this file involves 10.0.0.5 except the ARP reply, so try ip.src == 10.0.0.10 as well to see what the web server sent.

03Which requests came from curl?

Display: http.user_agent contains "curl"
tshark: tshark -r class2-filters.pcap -Y "http.user_agent contains \"curl\"" -T fields -e frame.number -e http.request.uri
Answer

Two requests: /index.html (frame 12) and /files/report.txt (frame 32). The browser-style request is /login, which got a 404 (frame 24). A tool user agent is not proof of anything, but it is a lead.

04Find the TLS server name. What service is it?

Display: tls.handshake.extensions_server_name
tshark: tshark -r class2-filters.pcap -Y tls.handshake.type==1 -T fields -e tls.handshake.extensions_server_name
Answer

api.llm-provider.test. The payload is encrypted but the SNI tells you the client called a hosted AI API. This is the AI-thread signal for today: name, bytes up, bytes down.

05Find the failed connection.

Display: tcp.flags.reset == 1
BPF:     "tcp[tcpflags] & tcp-rst != 0"
Answer

Frame 72: 10.0.0.10 sent RST,ACK from port 8080 to 10.0.0.5. A reset right after a SYN means the host answered and nothing listens there. Compare with Week 1: a SYN with no answer at all means filtered or down.

06Follow the first HTTP conversation.

Click frame 12 → Analyze → Follow → TCP Stream
Or: tcp.stream eq 0
Answer

You see the request and the 200 response as text. The book calls this one of its three favorite Wireshark features: read the conversation, not the packets.

07Export the file that was downloaded and hash it.

File → Export Objects → HTTP → report.txt → Save
shasum -a 256 report.txt
Answer

5b004bbccaa6e07cddd59eba5215952da0b60a2a2aaf02d079570c6f87217191. Record the hash and the frame number in your notes so another analyst can check your work.

08Capture filter versus display filter: what is different?

BPF (capture): host 10.0.0.10 and tcp port 80
Display:       ip.addr == 10.0.0.10 && tcp.port == 80
Answer

Same result on this file. The difference is when they apply. A capture filter decides what is saved, so what it drops is gone for good. A display filter only changes your view.

09Combine filters. Show web traffic from 10.0.0.5 that is not a TCP ACK-only packet.

Display: ip.src == 10.0.0.5 && tcp.port == 80 && tcp.len > 0
Answer

Two requests are GETs with data; frames with no data (the empty ACKs) disappear. Build filters progressively, as the book does.

10How many ICMP packets, and what are they?

Display: icmp
BPF:     icmp
tshark -r class2-filters.pcap -Y icmp.type==0 (replies)
Answer

Eight: four echo requests to 8.8.8.8 and four echo replies. The book's ICMP examples use the same pattern (icmp-echoreply).
